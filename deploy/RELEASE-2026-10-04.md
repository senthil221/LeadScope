# Workspace reliability release

This release improves the recruiting team's daily table work while preserving
role-specific ratings, stage-specific columns, private recruiter notes, existing
share tokens, and manually initiated mobile lookups.

## Changes

- Bulk edit accepts the same 2,000-row limit as selection and the database.
  Selection and export read bounded pages, preserve all filters, and reject
  detected partial/changing results. Exports remain capped at 10,000 profiles.
- Failed pasted cells retain their drafts and report the actual number saved.
  Field saves compare the previous value inside the database transaction.
  The profile form saves changed fields atomically.
- Search includes LinkedIn, email and phone, including pasted formatted values.
  The role grid holds at most 200 rows before continuing to the next page.
- Master Database has global contact/company/location/experience/client filters,
  an editable profile drawer, and links to the person's role memberships.
- Saved views retain filters and columns per role and stage in this browser.
  Switching stages clears filters; applying a saved view is explicit.
- Work queue links to due follow-ups, missing mobiles, stale stages and unrated
  profiles. It includes recruiter filters, setup completeness and worker health.
- Client review has search, sorting, stage and column controls, and 25-row pages.
  All candidate/custom columns start visible. Private notes stay excluded.
  Failed feedback saves retain drafts, support retry and prevent view changes
  while unsaved. Conflicting feedback writes are rejected.
- Import preview reports missing matching context. Role creation accepts a brief.
  Apollo can receive an existing email as matching context; no additional email
  lookup is started. Existing mobile-only request flags and provider order remain.
- CI runs lint, types, unit/API tests, isolated PostgreSQL tests and build.

## Deployment

Apply `supabase/migrations/20261003234008_workspace_reliability_and_reuse.sql`
before starting the new app image. It is a transaction containing additive
columns, triggers, indexes and RPCs, plus the corrected directory count function.
The previous app remains compatible with this migration. Keep a database dump
and tag the previous running image before changing the deployment.

The Hostinger installation has historically applied SQL directly, rather than
through a `supabase_migrations.schema_migrations` table. Record the applied file
checksum with the release backup. Do not replay older migrations on production.

Run from the VPS checkout:

```sh
docker compose -f deploy/docker-compose.yml build leadscope
docker compose -f deploy/docker-compose.yml up -d leadscope mobile-worker
```

For an application rollback, retag the retained pre-release image as
`deploy-leadscope:latest` and recreate both containers with `--force-recreate`.
Keep the additive database migration. Never drop production tables as rollback.

## Verification and limits

Regression coverage includes field conflict detection, atomic form rollback,
cross-role share rejection, private RPC permissions, identity/contact search,
55-row master pagination, queue totals, 2,000-row HTTP requests, partial-export
rejection, failed-paste drafts and client-feedback retry/pagination guards.

The database suite contains 45 intentionally skipped tests for retired campaign
behavior. Authenticated production checks are read-only; no paid lookup is
needed for release verification. Automated browser coverage is still limited
to unauthenticated flows, with API/component/database tests for the new features.
CI configuration is committed, but a hosted CI run is not implied by local tests.

Named views are browser-local. Work queue lists up to 200 open roles; role history
in a drawer lists up to 100 memberships. Shared review paginates rendering, but
the server still retrieves the complete authorized shortlist. Exact provider
credit usage is not fabricated: see `deploy/ENRICHMENT.md` for billing limitations.
Backup archive verification is not a substitute for an offsite restore drill.

## Follow-up: table controls and loading

Release 55504f8 removes Saved views from the role toolbar and hides Work queue
entirely, including redirecting /work to /clients and stopping its page queries.
Role column widths use a fresh preference version to discard the collapsed
72px layout; column visibility, order, density and candidate data are retained.
Resizing uses actual displayed widths, previews geometry during pointer movement
and commits once at release. Source/date/status have readable minimum widths.
Floating filters, columns and phone controls dismiss on outside clicks; content
accordions stay open. Stages without phone columns request only the lightweight
lookup summary, instead of fetching every visible candidate's lookup state.

Validation: lint, TypeScript, 247 unit/component tests and the VPS production
build passed. Brave verified pointer resizing (1133px to 1013px), width persistence
after reload, hide/show Source, outside-click and Escape dismissal, and the
Work queue redirect. Candidate records were not edited during these checks.
Three before-release table-visible reload samples were 976, 7171 and 1535ms;
after-release samples were 1050, 969 and 1336ms. These include browser/tool
latency and are spot checks, not a reliable percentage speedup or proof that all
intermittent network delays are resolved. Database HTTP probes from the app
container took 64, 11 and 8ms. No database migration was needed.
Rollback image: deploy-leadscope:before-table-fixes-20261004.
